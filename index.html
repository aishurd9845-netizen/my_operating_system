Process scheduling

What are we investigating?

A CPU core executes one thread at a time. When several processes are ready, the scheduler decides who runs next.

A CPU burst is a period of CPU execution before a process finishes or needs to wait. In this simplified lab, each process has one burst, and all arrive at time 0.

Scenario: a long video export blocks a notification

P1 represents a video export. P2 represents a notification task. P3 performs a search, and P4 scans a file.

Increase P1's burst time and run FCFS. Does the notification receive CPU time immediately, or must it wait?

Equal-arrival ties use the displayed order. Context-switch overhead is omitted. Time units are abstract, not seconds.

Unfinished processes

Why does FCFS delay small tasks?

Non-preemptive FCFS lets the running process finish its burst. A short task cannot interrupt a long task ahead of it. This demonstrates head-of-line blocking and the convoy effect.

Why does Round Robin feel more responsive?

A process receives at most one quantum before moving to the back of the ready queue if unfinished. Other processes get an earlier opportunity to run.

Interview: waiting time versus response time

Waiting time is the total time spent ready but not running. Response time is the delay until a process first receives CPU time. They are not generally the same.

Memory and page replacement

Why does a page need replacing?

Virtual memory maps virtual pages to physical frames. This lab has only three frames. A reference to a page absent from RAM causes a page fault.

If every frame is occupied, a replacement policy selects a victim. In a real system, a dirty victim may need writing back before the requested page can be loaded.

Experiment: what gets evicted?

Step through this reference string: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2. Compare FIFO's oldest-loaded rule with LRU's least-recently-used rule.

Storage and disk scheduling

Why does request order matter?

A file system maps names and metadata to stored data. On a traditional hard disk, moving the mechanical head takes time. Disk scheduling can reduce this movement.

This head-movement model applies to HDDs, not SSDs, which have no mechanical seek head.

Scenario: choose the nearest pending request

Deadlock and recovery

Busy is not the same as blocked

A process may hold one resource while waiting for another. If processes form a cycle of dependencies, progress can stop. This lab uses one instance of each resource.

Scenario: printer and scanner

P1 holds the printer. P2 holds the scanner. Let each request the other resource and inspect the result.

Interview: the four necessary conditions

Mutual exclusion, hold and wait, no preemption, and circular wait. Prevention removes at least one condition. Recovery acts after deadlock has occurred.

Permissions and system calls

Who is allowed to do what?

Applications request kernel services through system calls. The kernel checks credentials and permissions before accessing protected resources.
